# Qorgan: умный подбор подрядчиков

HackAlem AI 2026, case #79-lite: заказчик задаёт параметры мероприятия и получает до трёх доступных подрядчиков из официального каталога с детерминированным объяснением и проверяемым AI-дополнением.

## Задача и пользователь

Заказчику event-площадки нужно выбрать подрядчика из уже существующего каталога своего города. Длинный список не отвечает на вопросы о занятости, бюджете и пригодности для конкретного события. Сервис проверяет эти условия, показывает причины отсева и объясняет каждую рекомендацию фактами из профиля.

## Что реализовано

- Форма → `POST /api/recommend` → CSV → фильтрация → сортировка → карточки.
- Статусы `matched`, `no_category`, `no_eligible`; при неполной выдаче есть `shortfall`.
- `rejected[]` сохраняет **все** причины отсева: `busy`, `over_budget`, `format`, `language`, `duration`.
- Pipeline показывает, сколько профилей осталось после каждого последовательного этапа.
- Карточки показывают происхождение синтетических профилей и восстановленных города/цены.
- Каждое объяснение содержит 1–2 предложения: расчёт бюджета кодом и, при успешной проверке, профессиональный факт из описания, выбранный AI.
- При отсутствии credentials или сбое AI подбор продолжает работать с детерминированными объяснениями.

## Архитектура

`lib/catalog.ts` читает `data/contractors.csv` через PapaParse (`header: true`) и нормализует типы. `lib/search.ts` проверяет вход через Zod. `lib/match.ts` содержит чистый детерминированный matcher: точный каталог по городу и категории, все причины отсева, последовательный pipeline, сортировку и объяснения. `app/api/recommend/route.ts` обрабатывает запросы и ошибки. Форма находится в `components/SearchForm.tsx`.

Выбрал детерминированную фильтрацию, потому что календарь, бюджет и другие жёсткие ограничения должны проверяться гарантированно. AI вызывается только после фиксации top-3. Он не получает весь каталог и не управляет фильтрами, rejected, pipeline, ranking, статусом или shortfall. Route дополняет только поля объяснения уже выбранных карточек, сохраняя их порядок.

## AI-объяснения и проверка evidence

`lib/openai.ts` содержит единственный сетевой вызов: OpenAI Responses API через `client.responses.parse()` и `zodTextFormat`. SDK `openai` 7.23.0 совместим с Zod 4.6.5; версия Zod сохранена, downgrade не выполнялся. `lib/prompts.ts` содержит системный prompt. Пользовательский контекст и описания передаются отдельным JSON-сообщением как данные; инструкции внутри них запрещено выполнять.

Один пакетный запрос передаёт все выбранные 1–3 профиля: id, имя, стартовую цену, форматы, языки, часы и description. Контекст включает тип события, категорию, бюджет, необязательные длительность и язык. При `no_category` и `no_eligible` сеть не вызывается.

Strict Structured Outputs использует схему:

```ts
{ explanations: { id: string; distinctiveFact: string | null; evidence: string | null }[] }
```

Все поля required, отсутствующие значения представлены `null`, дополнительные поля запрещены. После SDK чистая функция `resolveExplanations(top3, rawModelOutput)` повторно проверяет ответ через Zod. Она не вызывает сеть и возвращает результат только для доверенных top-3 в исходном порядке. Неизвестные id игнорируются, дублирующийся id и пропущенный профиль получают fallback; невалидная общая схема даёт fallback для всех.

Evidence после trim должен содержать 10–150 символов и находиться в description после одинаковой нормализации: Unicode NFKC, lowercase, ё→е, типографские кавычки→обычные, тире→дефис, многоточие→три точки, NBSP/bullets→пробел, схлопывание whitespace. Нормализованный текст не показывается пользователю. И evidence, и факт проверяются кодом на рекламные фразы и личные сведения: семейное положение, детей, внешность, телосложение, привычки, здоровье, религию и политику. Многофразовый AI-текст отклоняется, а не обрезается до потенциально другого смысла.

`explanationSource: "ai"` выставляется только при принятом дополнении; иначе `"fallback"`. API также возвращает `explanationEvidence` с исходным фрагментом, либо `null`. Первое предложение всегда остаётся детерминированным: стартовая цена, бюджет и точный запас относительно стартовой цены. В многокарточной выдаче используются реальные различия: например, у Нами есть конференции, у Санджи той. У единственной карточки нет сравнительных превосходных утверждений. AI может добавить только второе предложение.

Общий AI deadline составляет 7000 мс, используется AbortController. Встроенные ретраи SDK отключены. После неудачной первой попытки допускается одна повторная попытка всего пакета, только если осталось больше 3000 мс; она использует остаток того же бюджета. Третьей попытки нет. Timeout, abort, сетевой сбой, refusal или неверный output приводят к fallback. Непроверенное дополнение отдельной карточки также заменяется fallback без нового запроса.

Для диагностики API отдаёт заголовки `X-AI-Attempts`, `X-AI-Retry`, `X-AI-Verified` и, для matched, `Server-Timing`. Ключи и SDK-ошибки в ответ не попадают.

## Данные и схема

В `data/contractors.csv` находятся 66 анонимизированных профилей официального датасета. Списки `categories`, `event_formats`, `languages`, `busy_dates` разделены `|`; `True`/`False` превращаются в boolean, пустой `max_hours` в `null`. CSV разбирается с учётом запятых, кавычек и переносов строк в описании. `max_hours: null` означает, что ограничение длительности присутствия не применяется.

Обязательный вход: `city`, `date`, `eventType`, `category`, `budgetKzt`. Необязательный: `durationHours`, `language`. Дата должна существовать в календаре и находиться в диапазоне `2026-09-23` — `2026-12-31`. Город, формат и язык проверяются по допустимым значениям; бюджет должен быть положительным целым числом. Длительность, если задана, должна быть целым числом от 1 до 24 часов. Категория проверяется Zod-схемой по Set категорий из реально загруженного CSV: неизвестная категория возвращает HTTP 400, а `no_category` означает отсутствие известной категории в выбранном городе.

## Фильтры и ранжирование

Каталог формируется по точному совпадению города и категории. Затем каждый профиль независимо проверяется на занятость, бюджет, формат, язык и длительность. В выдачу попадают только профили без причин отсева. Pipeline применяет эти проверки последовательно, поэтому кандидат учитывается на каждом этапе только один раз; в `rejected[]` у него может быть несколько причин.

Подходящие профили сортируются по возрастанию цены, затем при указанной длительности по убыванию запаса часов (`null` означает отсутствие лимита), затем по стабильному `id`. Возвращаются первые три. Рейтинги качества и вероятность выбора не вычисляются: таких данных нет.

## Технологии и системные требования

Next.js App Router, React, TypeScript strict, Tailwind CSS, Zod, PapaParse, OpenAI SDK. Для локального запуска нужны Node.js 24 и npm 11; проверено в этом окружении с Node.js 24.11.1 и npm 11.6.2.

## Установка и запуск

```powershell
npm install
Copy-Item .env.example .env.local
npm run dev
```

Открыть `http://localhost:3000`. Для production-сборки:

```powershell
npm run build
npm run start
```

`.env.example` содержит пустой `OPENAI_API_KEY` и `OPENAI_MODEL=gpt-5.4-mini`: именно эта API-модель прошла live smoke 23.09.2026. Для AI нужно заполнить ключ в локальном `.env.local`; модель берётся только из `process.env.OPENAI_MODEL`. Это настройка приложения, не модель агента Codex. Если ключ или модель отсутствуют/пусты, приложение работает с fallback без сети. Реальные env-файлы исключены из Git; `.env.example` ключа не содержит.

## Проверки

```powershell
npm run typecheck
npm run lint
npm test
npm run build
```

19 offline-тестов проходят без ключа и без сетевых моков. Matcher проверяется на реальном CSV: 66 уникальных профилей, ordered IDs, календарь, `max_hours: null`, статусы, максимум три результата, все причины отсева и последовательный pipeline. Проверяется валидация дат, бюджета, длительности и категории. Pure resolver тестируется на нормализации, fabricated/коротком/длинном evidence, unknown/duplicate/missing id, null, malformed output, запрещённых фактах и корректном ответе. Также проверяются strict JSON schema helper, неизменность входных данных, различимость fallback и предел предложений. Все четыре команды выполнены успешно.

Live smoke Demo A 23.09.2026: HTTP 200, модель `gpt-5.4-mini`, 3 проверенных AI-карточки, одна попытка, retry=false. Полная latency от отправки HTTP-запроса до чтения JSON: **4320 мс**; AI stage: **4161 мс**. IDs и все бизнес-поля совпали с matcher, evidence каждой карточки найден в её description, объяснения содержат по два предложения. Это один фактический замер, а не гарантия latency. Production HTTP-регрессия A/A2/B/C/no_category без credentials также прошла: AI attempts=0, все карточки fallback, Demo A **67 мс**. Страница production отвечает HTTP 200.

Отправить параметры через форму или `POST /api/recommend` с JSON. Реальные результаты локального API:

| B | Астана, `2026-09-23`, корпоратив, Флорист, 500 000 ₸, русский | `matched`: Хаку (300 000 ₸), один профиль в каталоге; синтетический badge. |

Пустой или неверный ввод возвращает HTTP 400 с понятной ошибкой; например, нулевой бюджет и дата вне диапазона. Ошибка чтения каталога возвращает HTTP 500 без стектрейса и секретов. В UI есть состояния загрузки, результата, некорректного ввода и ошибки сервера.

## Известные ограничения и деплой

Нет бронирования, базы данных, авторизации и semantic ranking. Проверка evidence подтверждает наличие цитаты, но не является полной семантической проверкой каждого утверждения модели; deny-list также не покрывает все возможные перефразирования личных сведений. При неразличимых структурированных параметрах fallback честно сообщает об отсутствии основания выделять профиль. Стартовая цена не является окончательной сметой. Timeout/retry реализованы, но live smoke прошёл с первой попытки: реальный сетевой timeout в нём не воспроизводился. Визуальная проверка в браузере не выполнена: браузерная поверхность недоступна. Деплой и URL ещё отсутствуют.
