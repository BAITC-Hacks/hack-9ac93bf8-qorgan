## 1. Контекст

Баллы дают ТОЛЬКО за то, что реально работает и видно в коде, а не в README.

Критерии оценки (100 баллов) — оптимизируй под них:
- Соответствие задаче и функциональность — 20
- Техническая реализация (реальный код, без имитации) — 25
- README и документация — 20
- Воспроизводимость (запуск из чистого клона) — 20
- Надёжность и безопасность — 15

## 2. Жёсткие запреты (нарушение = потеря баллов или дисквалификация)
1. НИКАКИХ заглушек, моков, захардкоженных ответов, фейковых задержек с готовым
   результатом, «TODO: подключить потом». Каждая функция реально работает.
2. НИКАКИХ ключей и секретов в коде. Только `process.env`. `.env` в `.gitignore`.
   Новая переменная → сразу в `.env.example` и в README.
3. Работаем ТОЛЬКО в текущем репозитории и ТОЛЬКО в ветке `main`.
   Не создавай ветки, git worktrees, не меняй remote.
4. Не вызывай OpenAI из браузера — только с сервера.
5. Не добавляй зависимости без необходимости. Каждую новую — в README
   (раздел «Использованные внешние материалы»).
6. Не делай рефакторинг и новые фичи без моего запроса.
7. Никаких фиктивных коммитов. Коммит = реальный рабочий результат.

## 4. Стек и команды
- Next.js (App Router) + TypeScript (strict) + Tailwind
- API-маршруты: `app/api/*/route.ts`
- Установка: `npm install`
- Разработка: `npm run dev` → http://localhost:3000
- Сборка: `npm run build` — запускай после КАЖДОГО изменения
- Линт: `npm run lint`
- Прод: `npm run build && npm run start`

## 5. Структура
- `app/` — страницы и API
- `lib/openai.ts` — ЕДИНСТВЕННОЕ место вызова модели
- `lib/prompts.ts` — все системные промпты
- `lib/` — остальная логика (расчёты, парсинг)
- `components/` — UI
- `data/` — данные задачи и примеры входа
- `README.md`, `AGENTS.md`, `.env.example`

## 6. Правила AI-части
- Модель берётся из `process.env.OPENAI_MODEL`, не хардкодь имя модели.
- Где результат модели нужен коду — требуй JSON по схеме, валидируй через `zod`.
  Невалидный ответ → одна повторная попытка → понятная ошибка.
- Числа и расчёты делает КОД, модель объясняет, классифицирует, извлекает.
- Таймаут на вызов модели. Ошибка API → понятное сообщение, страница не падает.
- Пользовательский текст в промпте отделяй от инструкций (защита от промпт-инъекций).

## 7. Надёжность и безопасность
- Валидируй ввод на сервере: пустой, слишком длинный, неверный формат/тип файла → 400
  с понятным текстом.
- Каждый API-маршрут в try/catch. Наружу — без стектрейсов и секретов.
- В UI всегда есть состояния: загрузка, ошибка, пустой результат.

## 8. Как работать
1. Перед кодом — план из 3–7 пунктов и список файлов, которые тронешь.
2. Один шаг → `npm run build` → исправь ошибки сам → проверь поведение.
3. После рабочего шага предложи коммит: `feat: ...` / `fix: ...` / `docs: ...`
   (конкретно, что сделано). Цель — коммит каждые 30–40 минут.
4. Не получилось дважды — остановись и опиши проблему. Не угадывай.
5. Объясняй ключевые решения одной фразой: «выбрал X, потому что Y».
   Я должен уметь защитить каждое решение перед жюри.
